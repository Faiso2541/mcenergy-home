# Home Customer Report

เว็บสำหรับให้ลูกค้าเข้ามาอ่านและดาวน์โหลดรายงานตรวจสอบบำรุงรักษาอุปกรณ์ (PDF) ของบริษัทตัวเอง

## โครงสร้างไฟล์

```
index.html      หน้าเว็บทั้งหมด (ไฟล์เดียวจบ)
reports.json    สารบัญรายงาน — สร้างจาก สร้างรายการรายงาน.bat
reports/        โฟลเดอร์เก็บ PDF แยกตามชื่อลูกค้า
assets/logo.svg โลโก้ประแจ (ใช้เป็น favicon ด้วย)
vercel.json     ตั้งค่า header สำหรับ Vercel
tools/          สคริปต์สร้าง reports.json
```

## บัญชีเริ่มต้น

| ผู้ใช้ | รหัสผ่าน | สิทธิ์ |
|---|---|---|
| `Admin` | `admin@1234` | จัดการผู้ใช้ / ลูกค้า / รายงาน / ดูประวัติการใช้งาน |
| `User` | `@12345` | ค้นหาลูกค้า + ใส่รหัสเข้าถึง + อ่าน/ดาวน์โหลด/เพิ่ม PDF + เปลี่ยนรูปตัวเอง |

**สิทธิ์ทั้ง 3 ระดับ**

- `admin` — ทุกอย่าง รวมประวัติการใช้งานย้อนหลัง 7 วัน
- `editor` — เหมือน user แต่แก้ชื่อที่แสดงและรูปประจำตัวของผู้ใช้คนอื่นได้
- `user` — ดูรายงานตามขอบเขตลูกค้าที่กำหนด เปลี่ยนได้เฉพาะรูปของตัวเอง

รหัสผ่านและรหัสเข้าถึงตรวจตัวพิมพ์ใหญ่-เล็กแบบตรงตัว ส่วนชื่อผู้ใช้ไม่สนตัวพิมพ์

ตอนสร้างผู้ใช้ กำหนดได้ว่าให้เห็นลูกค้าทั้งหมด หรือเฉพาะรายที่เลือก

ลูกค้าแต่ละรายมีรหัสเข้าถึง 6 หลักของตัวเอง ดูและแก้ได้ที่ จัดการระบบ → ลูกค้า & รหัสเข้าถึง

## ขึ้นเว็บ

**GitHub Pages** — อัปโหลดทุกไฟล์ในโฟลเดอร์นี้เข้า repo → Settings → Pages → Branch `main` / root

**Vercel** — New Project → Import repo → Framework Preset: `Other` → Root Directory: ปล่อยว่าง → Deploy

ทั้งสองแบบไม่ต้อง build อะไรทั้งสิ้น เป็น static site ล้วน

## เพิ่มรายงานใหม่

1. วางไฟล์ PDF ใน `reports/<ชื่อลูกค้า>/` ตั้งชื่อแบบ `2026-08-12_ตรวจเช็ค Chiller (PM).pdf`
2. ดับเบิลคลิก `สร้างรายการรายงาน.bat`
3. push ขึ้น GitHub — Vercel deploy ให้อัตโนมัติ

หรือถ้าเก็บไฟล์บน OneDrive ให้วางลิงก์แชร์ในแท็บ "รายงาน PDF" แทน ระบบจะแปลงเป็นลิงก์ดาวน์โหลดตรงให้เอง

รายละเอียดเพิ่มเติมดู `คู่มือ-ขึ้นเว็บ-GitHub-Pages.md`
